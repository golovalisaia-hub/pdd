# Экзаменационный комплект АВМ

## Опубликованный комплект

12 ноября 2026 года получены 160 ведомственных PDF с вопросами и 40 отдельных PDF с ответами и комментариями. Госавтоинспекция указывает, что опубликованные билеты утверждены главным государственным инспектором безопасности дорожного движения России и используются для теоретического экзамена. На странице отсутствует точная дата редакции. Идентификатор `mvd-abm-2026-11-12` фиксирует дату сверки опубликованного комплекта. [Страница билетов ABM](https://xn--80aebkobnwfcnsfk1e0h.xn--p1ai/mens/avtovladeltsam/abm)

В сборку вошли все 800 позиций, 2510 вариантов ответов в исходном порядке и 548 ведомственных иллюстраций. Иллюстрации извлечены из PDF и сохранены в WebP без уменьшения разрешения, с исходными обозначениями. Индексы правильных ответов взяты из 40 отдельных ведомственных PDF с комментариями. Тексты, порядок вариантов, индексы и наличие иллюстраций дополнительно сверены с Авто.ру. [Ведомственные PDF и их SHA-256](../data/abm/sources.json) · [Ключ для проверки сборки](../data/abm/answers.json) · [Независимая сверка](https://pdd.auto.ru/exam/)

Для каждого вопроса показан комментарий из ведомственного PDF. В 417 вопросах из комментариев есть переходы к соответствующим карточкам справочника.

Основание публикации приведено в разделе «Об использовании информации сайта» ведомственной страницы. МВД России разрешает воспроизводить материалы сайта, в том числе на других сайтах, при условии ссылки на первоисточник. Ссылка доступна в настройках PDD. Материалы сторонних тренажёров и выгрузок в сборку не входят. [Условия на сайте Госавтоинспекции](https://xn--80aebkobnwfcnsfk1e0h.xn--p1ai/mens/avtovladeltsam/abm)

Для проверки выпуска используется команда `npm run validate:bank -- --answers data/abm/answers.json`. Сборка включает оба режима. Авторские вопросы находятся в разделе «Билеты → Авторская практика».

## Подготовка файлов

Получите ведомственный комплект или разрешённую к использованию копию и сверяйте её с первоисточником. Зафиксируйте редакцию, дату сверки, издателя, условия использования и ссылку или реквизиты документа о правах. Сохраните исходные варианты ответа в исходном порядке. Сверьте рисунки с оригиналом и сохраните обозначения первоисточника. Укажите в `rights.terms` условия использования текста, иллюстраций и включённых пояснений, а также требования к указанию авторства.

Подготовьте два JSON-файла в UTF-8 и папку иллюстраций. `version` — идентификатор редакции, одинаковый в обоих файлах. Используйте новый идентификатор при замене редакции. В файле комплекта `source` — HTTPS-адрес источника. `editionDate` и `checkedAt` указываются в формате `ГГГГ-ММ-ДД`. Если издатель не указал дату редакции, задайте `editionDate: null` в обоих файлах. `ticket` и `position` нумеруются с единицы. `correct` нумеруется с нуля.

### Файл комплекта

В рабочем файле ровно 800 записей в `questions`. Ниже одна условная запись для примера формата.

```json
{
  "category": "ABM",
  "version": "идентификатор-редакции",
  "source": "https://example.org/abm",
  "provenance": {
    "publisher": "Наименование издателя",
    "editionDate": "2026-10-01",
    "checkedAt": "2026-11-11",
    "rights": {
      "terms": "Условия использования материалов",
      "evidence": "Ссылка или реквизиты документа"
    }
  },
  "questions": [
    {
      "ticket": 1,
      "position": 1,
      "text": "Формулировка из источника",
      "options": ["Первый вариант", "Второй вариант"],
      "correct": 1,
      "topic": "Тема ПДД",
      "image": "ticket-01/question-01.png"
    }
  ]
}
```

Укажите `image`, если у вопроса есть рисунок. Это путь относительно папки иллюстраций с разделителем `/`. Поддерживаются JPG, PNG и WebP. Дополнительные поля `explanation`, `simple` и `rules` содержат пояснение, краткое пояснение и массив ссылок на пункты ПДД. Пояснения добавляйте при наличии прав на их использование. Идентификаторы вида `abm-01-01` назначаются при импорте.

### Независимый ключ

Подготовьте `answers` из отдельного источника с 800 ответами для той же редакции. Укажите адрес источника ключа или реквизиты отдельного документа, индекс и текст правильного варианта, а также наличие рисунка в оригинале. Пример одной записи ниже.

```json
{
  "category": "ABM",
  "version": "идентификатор-редакции",
  "editionDate": "2026-10-01",
  "source": "https://example.net/abm-answers",
  "answers": [
    {
      "ticket": 1,
      "position": 1,
      "correct": 1,
      "answer": "Второй вариант",
      "hasImage": true
    }
  ]
}
```

## Импорт и проверка

Из корня проекта выполните следующие команды. `--assets` можно опустить, если иллюстрации лежат рядом с `pack.json` по указанным в нём путям.

```powershell
npm run import:abm -- --input "C:/data/abm/pack.json" --answers "C:/data/abm/answers.json" --assets "C:/data/abm/images"
npm run validate:bank -- --answers "C:/data/abm/answers.json"
npm run build
```

Импортёр проверяет категории, даты и 800 уникальных позиций, сверяет индексы и формулировки правильных ответов, проверяет наличие рисунков и полностью декодирует указанные файлы. После проверки он записывает `public/bank/abm.json` и локальные изображения в `public/bank/abm-assets/`. Имена изображений содержат SHA-256 файла. Храните исходный комплект и ключ вне `public/`. Для повторной проверки используйте тот же файл ключа, включая исходное форматирование.

`npm run validate:bank` без установленного комплекта сообщает о режиме практики и завершается успешно. С установленным комплектом команда требует путь к ключу, сверяет его контрольную сумму и заново проверяет ответы и локальные изображения. При ошибке импорта или проверки команда завершается с ненулевым кодом.

Подтверждение подлинности редакции, состава рисунков и прав остаётся за оператором, который сверяет файлы с источниками. Команды выполняют локальную проверку и подготовку файлов к сборке приложения.
