# Экзаменационный комплект АВМ

## Проверка источников 11 ноября 2026 года

Официальный комплект АВМ в поставку не вошёл. Приложение использует авторские тренировочные вопросы. Для импорта нужен подлинный комплект из 40 билетов по 20 вопросов с подтверждённой редакцией, независимым ключом ответов и основанием использования текста и иллюстраций.

- Госавтоинспекция Свердловской области указала ведомственный адрес билетов для категорий А, В, М, ВЕ и подкатегорий А1, В1. Старый адрес на `гибдд.рф` перенаправил на новый. При прямой проверке новый адрес вернул HTTP 403, а повторные попытки через поиск и Firecrawl завершились по таймауту. Получить текущий комплект, ключ и условия использования на этой странице не удалось. [Сообщение Госавтоинспекции](https://t.me/s/gibdd_66?after=12357), [страница билетов АВМ](https://госавтоинспекция.рф/mens/avtovladeltsam/abm).
- В открытом репозитории `etspring/pdd_russia` есть выпуск `V2026.Q3.0` от 2 сентября 2026 года. На дату проверки поле `license` в GitHub API было пустым, а запрос лицензии вернул HTTP 404. Право на включение файлов этого выпуска и соответствие всех 800 позиций текущей ведомственной редакции подтвердить не удалось. [Выпуск](https://github.com/etspring/pdd_russia/releases/tag/V2026.Q3.0), [метаданные репозитория](https://api.github.com/repos/etspring/pdd_russia), [условия лицензирования репозиториев GitHub](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).
- Сторонние тренажёры показывают по 40 билетов АВМ. «Рульно» сообщает о сверке 800 вопросов и иллюстраций с ведомственными PDF, полученными 15 сентября 2026 года. Дата утверждения редакции в их источнике не указана. Разрешение на перенос комплекта и изображений из тренажёра не найдено. [Сведения об источниках «Рульно»](https://rulno.ru/about), [условия использования «Рульно»](https://rulno.ru/terms), [каталог Авто.ру](https://pdd.auto.ru/exam/).
- Пункт 131 регламента МВД № 80 устанавливает 20 вопросов в билете, от двух до пяти вариантов и один правильный ответ на вопрос. Пункт 6 статьи 1259 ГК РФ содержит исключение для официальных документов госорганов. Основание использования отдельно проверяется для конкретной редакции и материалов, включая графику и комментарии. [Приказ МВД № 80](https://publication.pravo.gov.ru/document/0001202103230031), [текст регламента с изменениями](https://www.consultant.ru/document/cons_doc_LAW_380236/2b2d31b8226a6464a3bbbb04d6c66afb4a8668bf/), [часть IV ГК РФ](https://pravo.gov.ru/proxy/ips/?docbody=&nd=102110716).

## Подготовка файлов

Получите ведомственный комплект или разрешённую к использованию копию и сверяйте её с первоисточником. Зафиксируйте редакцию, дату сверки, издателя, условия использования и ссылку или реквизиты документа о правах. Сохраните исходные варианты ответа в исходном порядке. Сверьте рисунки с оригиналом и используйте изображения без сторонних логотипов и водяных знаков. Укажите в `rights.terms` условия использования текста, иллюстраций и включённых пояснений, а также требования к указанию авторства.

Подготовьте два JSON-файла в UTF-8 и папку иллюстраций. `version` — идентификатор редакции, одинаковый в обоих файлах. Используйте новый идентификатор при замене редакции. В файле комплекта `source` — HTTPS-адрес источника. `editionDate` и `checkedAt` указываются в формате `ГГГГ-ММ-ДД`. `ticket` и `position` нумеруются с единицы. `correct` нумеруется с нуля.

### Файл комплекта

В рабочем файле ровно 800 записей в `questions`. Ниже одна условная запись для примера формата.

```json
{
  "category": "ABM",
  "version": "идентификатор-редакции",
  "source": "https://example.org/abm",
  "provenance": {
    "publisher": "Наименование издателя",
    "editionDate": "2026-10-01",
    "checkedAt": "2026-11-11",
    "rights": {
      "terms": "Условия использования материалов",
      "evidence": "Ссылка или реквизиты документа"
    }
  },
  "questions": [
    {
      "ticket": 1,
      "position": 1,
      "text": "Формулировка из источника",
      "options": ["Первый вариант", "Второй вариант"],
      "correct": 1,
      "topic": "Тема ПДД",
      "image": "ticket-01/question-01.png"
    }
  ]
}
```

Укажите `image`, если у вопроса есть рисунок. Это путь относительно папки иллюстраций с разделителем `/`. Поддерживаются JPG, PNG и WebP. Дополнительные поля `explanation`, `simple` и `rules` содержат пояснение, краткое пояснение и массив ссылок на пункты ПДД. Пояснения добавляйте при наличии прав на их использование. Идентификаторы вида `abm-01-01` назначаются при импорте.

### Независимый ключ

Подготовьте `answers` из отдельного источника с 800 ответами для той же редакции. Укажите адрес источника ключа или реквизиты отдельного документа, индекс и текст правильного варианта, а также наличие рисунка в оригинале. Пример одной записи ниже.

```json
{
  "category": "ABM",
  "version": "идентификатор-редакции",
  "editionDate": "2026-10-01",
  "source": "https://example.net/abm-answers",
  "answers": [
    {
      "ticket": 1,
      "position": 1,
      "correct": 1,
      "answer": "Второй вариант",
      "hasImage": true
    }
  ]
}
```

## Импорт и проверка

Из корня проекта выполните следующие команды. `--assets` можно опустить, если иллюстрации лежат рядом с `pack.json` по указанным в нём путям.

```powershell
npm run import:abm -- --input "C:/data/abm/pack.json" --answers "C:/data/abm/answers.json" --assets "C:/data/abm/images"
npm run validate:bank -- --answers "C:/data/abm/answers.json"
npm run build
```

Импортёр проверяет категории, даты и 800 уникальных позиций, сверяет индексы и формулировки правильных ответов, проверяет наличие рисунков и полностью декодирует указанные файлы. После проверки он записывает `public/bank/abm.json` и локальные изображения в `public/bank/abm-assets/`. Имена изображений содержат SHA-256 файла. Храните исходный комплект и ключ вне `public/`. Для повторной проверки используйте тот же файл ключа, включая исходное форматирование.

`npm run validate:bank` без установленного комплекта сообщает о режиме практики и завершается успешно. С установленным комплектом команда требует путь к ключу, сверяет его контрольную сумму и заново проверяет ответы и локальные изображения. При ошибке импорта или проверки команда завершается с ненулевым кодом.

Подтверждение подлинности редакции, состава рисунков и прав остаётся за оператором, который сверяет файлы с источниками. Команды выполняют локальную проверку и подготовку файлов к сборке приложения.
